# Index API reads for large-zone browsing

The web console must support complete paginated browsing of large zones, while the upstream HTTP API provides no pagination; fetching a whole zone for every page would repeat that work. DANS will maintain a rebuildable RRset browsing index in its existing PostgreSQL database, populated exclusively through PowerDNS API reads, with no direct access to the PowerDNS database or additional indexing service. The index serves browsing and filtering only: PowerDNS remains authoritative for DNS state, editors fetch the current complete RRset, and authorization continues to use current policy independently of indexed DNS data.

Build the index on first access, target affected-RRset refresh within five seconds of successful DANS writes, and fully refresh zones being viewed every five minutes or on manual request. Keep prior browsing results visibly stale during refresh failures; the index does not supply live editing state or stronger write-concurrency guarantees. This accepts eventual browsing consistency and periodic whole-zone reads to preserve the API-only upstream boundary without fetching a complete zone for every page.

Implementation publishes complete staged generations with PostgreSQL leases and lifetime/revision fences. Each instance runs bounded full-zone and affected-RRset read workers independently, so a full collection does not occupy the affected-read loop. Browser pages contain at most 100 complete RRsets; signed cursors bind filters and indexed revision and explicitly reject obsolete continuation. Real API-only capacity and cross-instance mutation measurements are recorded in the [verification note](../../openspec/changes/archive/2026-09-23-add-web-console/verification.md).
